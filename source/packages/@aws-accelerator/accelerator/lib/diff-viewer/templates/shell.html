How to use LZA CDK Diff Viewer

⚠️ Experimental feature. This viewer is a review aid, not a safety gate. It highlights what the synthesized CloudFormation templates appear likely to change relative to the deployed stacks, but it does not enforce any outcome. Pair it with authoritative controls. Use stack policies to protect specific resources from unintended replace or delete actions, and use CloudFormation change sets to confirm exactly which resources will be created, modified, or deleted at deploy time. Together these ensure the changes applied by CloudFormation match the changes you intended.

Sidebar — finding stacks

  • Stacks are grouped by section (NetworkVpc, Security, Logging, etc.). Click a section header (▼/▶) to collapse or expand it.
  • The Modules section (when present) lists module runner dry-run output (TGW associations, Macie, SSM, etc.). Click a module to view its dry-run text. Modules with real adds/removes are marked changed; SKIPPED (config-unchanged) modules show as unchanged.
  • Click a stack name to open its full diff.
  • Search filters by stack name or section.
  • Filter button: Unreviewed (default), Changed, Unchanged, Reviewed, All.
  • Drag the sidebar edge to resize. Click the ◀ button in the sidebar header to collapse the whole sidebar; the floating ▶ button in the top-left brings it back. Preference saved per browser.

Review workflow

  • Each stack has a Reviewed checkbox — tick to mark as reviewed (strikethrough + dim). Ticking a checkbox also collapses that stack's detail row on the summary page so you can move on.
  • Unchanged stacks are auto-marked as reviewed.
  • Stacks with only Lambda S3Key churn (asset hash rotation), AcceleratorVersion SSM bumps, or Custom::* UUID-only changes are treated as unchanged.

CloudFormation Diff Summary (top of sidebar)

The summary page has two collapsible sections (both expanded by default). Click a section title to collapse; click again to expand.

  • Critical Networking Changes — per-stack table of networking resources that will be deleted, replaced, conditionally replaced, or orphaned. Each row has its own expand chevron showing resource type, logical ID, and the properties that trigger any replacement. If you collapse the whole section while changes exist, an inline ⚠️ Critical networking changes exist — expand to review warning stays next to the title.
  • Stacks Requiring Review — every stack that touches a tracked resource type. Layout mirrors Critical Networking Changes: two-column table with an expand chevron per stack and one badge + resource type + logical ID line per resource. Paginated 25 per page.
    • Filters block at the top of the card holds the stack search box, the Unreviewed/Reviewed/All filter, and a collapsible Resource Types to Track chevron (closed by default). Inside are Select all and Clear all buttons plus one checkbox per resource type discovered in the diff. Tweaking any of these updates the table immediately.
    • Default selection is every resource type.
  • Scope — total accounts and regions affected.

Stack diff view

  • Sections are collapsible (▼/▶): Parameters · Conditions · IAM Statement Changes · Security Group Rule Changes · Resources · Outputs · Noise.
  • Resource cards with a red border are destructive — they will be deleted, replaced (definitely or possibly), or orphaned. Click the card header to expand property-level diffs.
  • Action badges: Will Create Will Update Will Destroy Will Replace May Replace.
  • Replacement banners explain when a change forces delete-and-recreate, and list the triggering properties.
  • Each property change shows the old value, new value, and an expandable full JSON diff. 📋 Old / 📋 New buttons copy the raw JSON to the clipboard.
  • IAM Statement Changes and Security Group Rule Changes tables show additions and removals as full-row highlights.
  • Noise section (collapsed by default) contains low-signal churn — Lambda code bundles, version parameters, CDK custom-resource UUIDs.

Diff colors (colorblind-safe)

  • Red with - prefix and left border — removal
  • Blue with + prefix and left border — addition
  • Muted italic — context / identity line

Export and share (top of Diff Summary)

  • ⬇️ Markdown — downloads a formatted summary with destructive and networking change tables, suitable for change-approval tickets or COE docs.
  • ⬇️ JSON — downloads the full structured impact report for programmatic consumption.
  • URL review state — if you open the viewer with a #r=<indices> fragment appended to the URL, those stack indices load as already-reviewed. Useful for scripting or hand-crafted review links.

Tips

  • ☀️/🌙 toggles light/dark theme (saved per browser).
  • Selected resource-type filters, the sidebar collapse state, and theme preference are all saved in localStorage for this file URL. Review-state checkboxes are in-memory only (share progress via the #r=<indices> URL fragment).
  • The HTML is fully self-contained and works offline — no network requests are made.
