    Optional Readonlyenable

    enable?: boolean

    Legacy switch that controls both EKS Audit Log Monitoring and EKS Runtime Monitoring together.

    Remarks

    This single flag drives both the EKS_AUDIT_LOGS and EKS_RUNTIME_MONITORING GuardDuty features. Use the granular auditLogs and runtimeMonitoring properties instead to control them independently. When enable is defined it takes precedence, and auditLogs / runtimeMonitoring must not also be set.

    Deprecated

    Use the granular auditLogs and runtimeMonitoring properties instead to control EKS Audit Log Monitoring and EKS Runtime Monitoring independently.

    Optional ReadonlyauditLogs

    auditLogs?: boolean

    (OPTIONAL) Controls whether GuardDuty EKS Audit Log Monitoring (EKS_AUDIT_LOGS) is enabled.

    Remarks

    Used only when the legacy enable property is not set. When omitted, the feature is not included in the GuardDuty request at all (neither enabled nor disabled) — it is left unmanaged, and its feature name is not sent to Regions/partitions that may not support it. Set to false to explicitly disable it.

    Optional ReadonlyruntimeMonitoring

    runtimeMonitoring?: boolean

    (OPTIONAL) Controls whether GuardDuty EKS Runtime Monitoring (EKS_RUNTIME_MONITORING) is enabled.

    Remarks

    EKS Audit Log Monitoring and EKS Runtime Monitoring are distinct GuardDuty features with different prerequisites, pricing, and regional availability. Used only when the legacy enable property is not set. When omitted, the feature is not included in the GuardDuty request at all (neither enabled nor disabled) — it is left unmanaged, and its feature name is not sent to Regions/partitions that may not support it. Set to false to explicitly disable it (sends EKS_RUNTIME_MONITORING as DISABLED).

    In Regions/partitions where EKS Runtime Monitoring is not available (for example us-iso-east-1), OMIT this property rather than setting it to false: an explicit false still sends the EKS_RUNTIME_MONITORING feature name, which GuardDuty rejects there with "provided feature names are invalid", whereas omitting it keeps the name out of the request so other EKS features (such as EKS Audit Logs) can still be enabled.
